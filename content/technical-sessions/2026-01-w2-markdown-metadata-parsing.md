## 🧠 What I Learned
New understanding, patterns, or insights:
- I looked at the the lexer provided by marked. How the tokens provide a type such as heading or paragraph
- In the original typescript file generated by Cursor it created a function to extract Markdown metadata. It did not use a separate package to extract the metadata. Instead it used regex. 
- I have, however, discovered that using a separated npm package such as gray-matter is better for the metadata extraction
- Marked is designed to parse Markdown not front-matter 
- If I want to add the table of contents I have to use marked to get the tokens, identify the tokens that are headings and add them to the front-matter metadata

## 😕 What Challenged or Confused Me
Things that slowed me down or felt unclear:
- The code generated by Cursor AI seems to achieve a goal but whether it is the correct approach is debatable
- It is a good exercise to go through the code generated by Cursor AI - you try and see what it is trying to achieve. But you should also not buy-in to everything. 
- I need to think about how I would structure the processing. Retrieving the metadata using gray-matter is the easy part. Using marked to retrieve the headings works fine but then to mutate the metadata later again requires some thinking in terms of the processing. 

## 🔁 What I'd Do Differently
If I repeated today, I would:
- If I were to create utilities to process Markdown using `marked` I would consider breaking down the processing into smaller chunks. With smaller chunks I can be specific with my instructions to the AI agent. Letting the AI agent decide on all things can be problematic
